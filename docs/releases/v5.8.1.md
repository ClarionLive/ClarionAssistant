# Clarion Assistant 5.8.1

**A patch release, and it fixes something 5.8 broke.** If you installed 5.8 and Clarion now stops at startup with *"Could not load file or assembly 'ClarionMarkdownEditor.dll'"*, this is the release that repairs it &mdash; and it repairs the damage in place, so a normal install is all that is needed.

The bundled **Markdown editor also moves to [v1.3.0](https://github.com/msarson/ClarionMarkdownEditor/releases/tag/v1.3.0)**, which adds auto-refresh, remembered view preferences, and resizable panes.

**Supported:** Clarion 10, 11, 11.1, and 12 (32-bit IDE).

> Nothing else changed. The Clarion Assistant addin itself is byte-identical to 5.8 &mdash; same binaries, same version stamp (5.8.1137). The only differences are in the installer's own logic and the Markdown editor it carries.

---

## The bug

Installing 5.8 could leave `accessory\addins\MarkdownEditor` holding **exactly one file** &mdash; `ClarionMarkdownEditor.addin`, the manifest &mdash; with none of the assemblies it names. Clarion reads that manifest at startup, tries to load the DLL that should sit beside it, and stops with two dialogs:

```
The addin 'ClarionMarkdownEditor.dll' could not be loaded:
System.IO.FileNotFoundException: Could not load file or assembly
'...\MarkdownEditor\ClarionMarkdownEditor.dll' or one of its dependencies.
The system cannot find the file specified.
```

```
Cannot create object: ClarionMarkdownEditor.RegisterIconsCommand
```

The second is the follow-on from the first. **The IDE does not start.**

### Why it happened

The installer decides whether to install the Markdown editor by reading the version out of any copy you already have, so that a newer copy of Mark Sarson's editor is never silently downgraded. That check was correct in isolation, and wrong in the way it was wired.

The editor's files are declared as a single wildcard entry, and Inno Setup evaluates an entry's `Check` function **once per file that the wildcard expands to**, at install time. `ClarionMarkdownEditor.addin` sorts alphabetically first. So the manifest was written &mdash; and every remaining file of the same wildcard then re-ran the check, found the manifest that had *just been written* reporting the version being installed, concluded "you already have this, leave it alone", and was skipped.

The gate destroyed its own precondition. One file in, twelve files skipped.

The payload was never missing from the installer: 5.8 packed all thirteen Markdown editor files correctly. They were skipped on the way out, not absent on the way in.

### Why reinstalling 5.8 did not help

Once that lone manifest existed, it kept reporting the current version, so every subsequent 5.8 install read it as up to date and skipped the payload again. The broken state was precisely the state the repair logic refused to repair.

### The fix

Two changes, and both are needed:

- **The decision is made once per Clarion version and then frozen.** The first evaluation necessarily happens before the install has written anything, so the answer reflects the folder you actually arrived with rather than one the installer has begun modifying.
- **A manifest with no assembly beside it is now treated as damage, not as an install.** There is nothing to downgrade in that state, so it is repaired unconditionally. This is what recovers machines already broken by 5.8 &mdash; without it, the frozen decision would protect new installs while abandoning everyone who already hit the bug.

The never-downgrade guarantee is unchanged: a copy of the editor **newer** than the bundled one is still left alone.

## Markdown editor v1.3.0

The bundled editor moves from v1.2.0 to **[v1.3.0](https://github.com/msarson/ClarionMarkdownEditor/releases/tag/v1.3.0)** &mdash; auto-refresh, remembered view preferences, and resizable panes.

As before, it installs into its own `accessory\addins\MarkdownEditor` folder rather than under Clarion Assistant, it is optional at install time, and **if you already run a newer build than the one bundled here, yours is kept**. `THIRD-PARTY-NOTICES.md` records the new version and the MIT licence travels with the payload.

## If you were affected

Install 5.8.1 over the top &mdash; it detects the incomplete folder and completes it. No manual cleanup is required.

If you would rather not wait, or you do not want the editor at all, deleting the whole `accessory\addins\MarkdownEditor` folder from the affected Clarion root also restores startup: Clarion starts cleanly with the folder absent.

## Thanks
