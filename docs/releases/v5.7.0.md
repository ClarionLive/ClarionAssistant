# Clarion Assistant 5.7

5.7 is a parity-and-reliability release. The **CA Embeditor answers Ctrl+J and Ctrl+B** the way the native embeditor always has, **Errors-pane navigation** keeps working once it has opened a generated `.clw`, and a language-server call that could **freeze the IDE for close to a minute** on the first embed save is gone. Two community PRs land — go-to-definition no longer resolves to an unrelated procedure's local, and the editor finally follows Clarion's *live* font. The **installer** stops letting a row install the wrong version's build, and handles more than one installation of the same version. Underneath, the Windows-1252 encoding sweep is finished, and collapsed folds are actually restored when you reopen a procedure.

**Supported:** Clarion 10, 11, 11.1, and 12 (32-bit IDE). The installer lets you pick which version(s) to install.

---

## Highlights

### ⌨️ Ctrl+J and Ctrl+B walk the filled embeds ([#185](https://github.com/ClarionLive/ClarionAssistant/issues/185))

The native Clarion embeditor jumps to the next filled embed point with **Ctrl+J** and the previous one with **Ctrl+B**. The CA Embeditor answers the same two keys now, so the muscle memory carries over — wrapping at either end, acting on whichever split pane has focus. A walk over *every* embed point, filled or not, is available as **Next/Previous Embed (any)** in the gear panel's Keyboard section, unbound by default.

Ctrl+J was already spoken for: it opened the code-snippet picker, because that is what classic Clarion's **text** editor uses it for — the same key, two different Clarion surfaces. The picker moves to **Ctrl+Shift+J** and moves out of its own hard-wired interceptor into the rebindable command table, so it now appears in the Keyboard section alongside everything else, is covered by the panel's conflict detection, and can be put straight back on Ctrl+J if you prefer. Help text renders whichever chord the picker is actually bound to, so it cannot go stale again.

### 🧭 Errors-pane navigation survives opening a generated `.clw`

With build errors in two procedures, clicking a row for the second procedure opens the generated `.clw` — correct, since that error is in generated code outside any embed. After that, rows belonging to the *first* procedure appeared to do nothing at all.

The reveal was computing the right line the whole time. Raising the embeditor only re-ordered the editor surface inside its host panel, which is invisible while another document is in front — and the embeditor is not a tab in its own right but a view *inside* the application window, so bringing that window forward still left whichever view was last active on screen. Both levels are handled now.

Underneath was the real defect: opening the `.clw` closes the native embed, leaving the editor holding a procedure's text with nothing behind it. It looked healthy enough to reveal into, and landing there was worse than the original symptom — **Save** reported "nothing to save" and **Cancel** blanked the buffer. An Errors row now confirms the native embed is genuinely still open (the same test Save uses, so the two cannot disagree) and hands the row to Clarion's own navigation when it isn't, which re-opens the embeditor properly.

### ⏱️ A language server call can no longer freeze the IDE for a minute

Saving or cancelling an embeditor froze the IDE for close to a minute — **measured at 57.7 seconds** — on the first one of each Clarion session. The cause was a synchronous wait on an asynchronous language-server call, made from the UI thread. An audit then found **twelve** such call sites rather than the two originally reported, so the whole pattern is corrected rather than one more symptom, with a bounded cap in place of an unbounded wait.

### 🔎 Go-to-definition stops resolving to an unrelated local ([#182](https://github.com/ClarionLive/ClarionAssistant/pull/182))

Go-to-definition's CodeGraph fallback could jump to a local variable or parameter belonging to some *other* procedure instead of reporting no definition — arbitrary and index-order-dependent, so the target could move between re-indexes with the code unchanged. It fired exactly where landing anywhere is most wrong: on a name that is genuinely undeclared. The guard already existed and was already used by the sibling hover path; the definition path had simply never called it. Module- and global-scope variables are unaffected.

### 🔤 The editor follows Clarion's live font ([#183](https://github.com/ClarionLive/ClarionAssistant/pull/183))

"Follow Clarion's editor options" never worked for the font: it read a property the current Options dialog does not write to, so changing the font in Options changed nothing the editor used. It now reads the value the dialog actually writes — the same one the native editor windows use — and an IDE font change reaches open editors immediately instead of needing the checkbox toggled off and on. The font fields also gray out and show the effective value while following.

### 📦 The installer stops a row installing the wrong build

Each row on the paths page installs the addin built *for that Clarion version*, compiled against that version's own IDE assemblies. Nothing said so, and the rows are freely editable — so pointing the "Clarion 10 folder" row at a Clarion 12 installation looked reasonable and produced an addin that could not load. The page now says the builds are not interchangeable and checks what you entered: a folder whose version doesn't match its row is named, told which row it belongs in, and warned about before anything is written. A folder whose version cannot be determined is left alone rather than blocked.

**More than one installation of the same version** is supported too — the gap 5.5's known issues warned about. Each row accepts several folders separated by semicolons, and the **`+`** button picks one for you, including the first (which is why the separate Browse button is gone). Everything `+` adds is ordinary editable text, so a wrong entry is corrected or removed in place. The first folder on a row is installed into and the rest receive a copy once the install finishes, with the list remembered for next time so a second tree doesn't quietly keep an old addin.

## 🐞 Fixed

### Editor & Embeditor

- **Your chosen font is no longer overwritten while following the IDE.** Making the font fields display the IDE's *effective* value opened a way to lose your own preference: the panel read the font straight off the fields when saving, and being grayed out doesn't prevent that — so with following on, changing any unrelated setting (the minimap, word wrap, a formatter option) persisted the IDE's font as *your* stored preference, permanently. Cursor-behind-EOL had the same shape and is fixed with it. Found in review of #183 and fixed before release.
- **Collapsed folds are restored when you reopen a procedure.** Fold state saved correctly and always loaded back empty — it was written with keys that could not be read back. Regions, `OMIT`/`COMPILE` blocks, procedures, routines and structures all survive a reopen now.
- **An ambiguous fold is refused rather than collapsing the wrong region.** A fold is identified by the text of its start line, which is effectively unique for `!REGION Setup cards` and not remotely unique for `Rec GROUP`, a bare `CODE`, or an `IF` — generated Clarion repeats structure headers constantly. Recovery now requires exactly one candidate in its window and declines when there are several. Declining to restore a fold is a small annoyance; collapsing the wrong one is the failure the fingerprint exists to prevent.
- **A WebView2 post-after-dispose race on closing an embeditor tab.** A background continuation could still be posting to the editor after teardown had begun. Two bugs compounded: a non-null field does not prove the control is undisposed, and `InvokeRequired` on a control whose handle was just destroyed returns `false` — not because the caller was already on the UI thread, but because there was no handle left to compare against — so the post called an STA COM object directly from a thread-pool thread mid-teardown. The single chokepoint every host→page message funnels through now checks for disposal before trusting that. *(Andrew Santarelli)*

### Language server & diagnostics

- **A global declared in an application's global data is no longer flagged `'X' is not declared in this file.`** while hovering the same word correctly described it as a global. That split is upstream — the diagnostic and hover resolve globals through two different paths — and is reported as [Clarion-Extension issue 396](https://github.com/msarson/Clarion-Extension/issues/396). Until it lands, the assistant suppresses that one message when it can point at a genuine declaration of the name in the application's PROGRAM module. Deliberately narrow: only that exact message is considered, and a name that is only ever a *local* somewhere else clears nothing, so a real typo is still flagged.

### Reliability

- **Clarion source encoding — the sweep is finished.** .NET only auto-detects an encoding from a byte-order mark, and Clarion source is Windows-1252 without one, so every read that passed no encoding decoded high-bit characters to `U+FFFD`. Two earlier passes each believed they had found them all (four, then seven); this is the full sweep of the main assembly, **nineteen** further reads. Two were read-modify-**write**: the text came back with a replacement character, was rewritten with a class name substituted, and the original byte was gone. Another was the path that pushes on-disk text back into the language server when an embeditor tab closes — the same defect an earlier fix had removed, reintroduced on every tab close.
- **Reads are cheaper.** Detecting an encoding is not a quick sniff: it read the whole file and decoded it once purely to test whether the decode succeeded, then discarded the result — so every read opened and decoded the file twice and threw away a full byte array and string. On a generated `.clw` both discards were large enough to reach the large-object heap, once per change on the sync path. One read, one decode, keep the result.
- **CA Search opens in your theme instead of always dark** ([#181](https://github.com/ClarionLive/ClarionAssistant/issues/181)). Results defaulted to dark and relied on a theme-*changed* broadcast to correct themselves, which never arrives for a light-mode user who hasn't toggled since startup — so every results tab stayed dark for its whole life. The view resolves the assistant's saved theme when it is created now.

## ⚠️ Known issues

- **Native Access Violation in Clarion's Generator on closing an embeditor** ([#179](https://github.com/ClarionLive/ClarionAssistant/issues/179)) — "Internal error: Restore Procedure". Still open. The WebView2 post-after-dispose race fixed in this release was a real, distinct race but not the whole story; this reproduced after that fix was deployed, and is likely the same underlying step behind the stale window-designer error icons in [#142](https://github.com/ClarionLive/ClarionAssistant/issues/142).
- **Cancel on an embeditor you have switched away from and back can blank the buffer.** A second Cancel completes normally and re-opening is fine; no application data is affected. The Errors-pane route into this state is closed in this release, but switching documents away and back reaches the same non-live state, where Save reports "nothing to save" and Cancel does not restore cleanly.
- **The `.app` globals diagnostic fix above is a workaround**, not the cure — it is scoped to that one message and will be removed once [Clarion-Extension issue 396](https://github.com/msarson/Clarion-Extension/issues/396) ships.

## 📦 Install

1. Download **`ClarionAssistant-5.7-Setup.exe`** below (code-signed).
2. Close the Clarion IDE.
3. Run the installer and pick your Clarion version(s) (10 / 11 / 11.1 / 12). Each row installs the build for **that** version — if you have two installations of the same version, add both folders to that row with the **`+`** button.
4. Start Clarion — the **Clarion Assistant** pane docks automatically (Tools → Clarion Assistant, or Ctrl+Alt+C).

Upgrading from 5.1–5.6 installs cleanly over the top.
